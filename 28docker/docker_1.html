Docker 환경 비교: 개발용(Dev) vs 배포용(Prod)

가장 큰 차이는 "코드를 어디서 가져오는가"와 "성능/보안을 위한 구성 요소"에 있습니다.

비교 항목 개발용 (Development) 배포용 (Production)
코드 위치 내 컴퓨터의 폴더 (로컬 파일) 도커 허브의 이미지 (박제된 파일)
수정 반영 파일 저장 시 즉시 반영 (Hot Reload) 이미지 새로 빌드 & 푸시 필요
Nginx 존재 없음 (각 포트로 직접 접속) 있음 (80포트 대문 역할)
용도 빠른 코딩과 디버깅 팀원 공유 및 실제 서비스 운영

1. 개발자용 (유연함)

  • Volumes: ./src:/app/src 처럼 내 폴더를 컨테이너에 연결합니다.
  • Build: build: . 옵션으로 내 컴에서 직접 빌드합니다.
  • 장점: 오타 하나 고치고 새로고침하면 바로 확인 가능!

2. 배포용 (안전함)

  • Image: image: 77eileen/... 처럼 이미 만들어진 이미지를 가져옵니다.
  • Nginx: 정적 파일(HTML/CSS)을 효율적으로 서빙하고 보안을 강화합니다.
  • 장점: 내 컴에 코드가 없어도 팀원 누구나 똑같이 실행 가능!

핵심 설정 차이 분석

① 로컬 코드 연결 (Volumes)

개발용에서는 - ./src:/app/src 설정을 사용하여 컨테이너가 내 컴퓨터의 파일을 직접 읽게 합니다. 반면 배포용에서는 이 줄을 삭제하여 이미지 안에 들어있는 고정된 코드만 실행하게 합니다.

② 정적 파일 처리 (Static Files)

# 배포용에만 있는 설정
- static_volume:/app/static

배포용에는 Nginx와 Django가 HTML, 이미지 같은 정적 파일을 서로 주고받기 위한 전용 통로(Shared Volume)를 만듭니다. 이는 실제 서비스 속도를 높여줍니다.

③ 문지기 Nginx

배포용에 추가된 Nginx는 사용자가 80번 포트로 들어왔을 때 백엔드(Django, FastAPI)로 안전하게 길을 안내해주는 역할을 합니다. 개발용은 편의를 위해 각각의 포트(8000, 8001)로 직접 들어갑니다.

이미지를 도커 허브에 올리셨다면, 이제 팀원들은 배포용(Prod) 실행만으로 질문자님과 완벽히 동일한 결과물을 보게 됩니다!
